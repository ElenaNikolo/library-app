# Βιβλιοθήκη

Εφαρμογή δανεισμού βιβλίων για μια μικρή βιβλιοθήκη. Τελική εργασία για το
Coding Factory 10 του Οικονομικού Πανεπιστημίου Αθηνών.

Ο κατάλογος είναι ανοιχτός σε όλους. Τα μέλη εγγράφονται, βρίσκουν ένα βιβλίο
και υποβάλλουν αίτημα δανεισμού. Το προσωπικό εγκρίνει το αίτημα, παραδίδει ένα
αντίτυπο και καταγράφει την επιστροφή. Ο διαχειριστής διαχειρίζεται επιπλέον
τους λογαριασμούς των χρηστών.

Το README καλύπτει το stack, τις προϋποθέσεις, τις ρυθμίσεις, την εγκατάσταση,
το build και το deploy, τους ρόλους, τις λειτουργίες και τη δομή του project.

## Stack

- **Γλώσσα backend:** Python 3.14
- **Frameworks / βιβλιοθήκες backend:**
  - FastAPI 0.141 (REST API)
  - SQLAlchemy 2.0 (ORM)
  - Pydantic Settings 2.15 (ρυθμίσεις από `.env`)
  - PyJWT 2.13 (JSON Web Tokens)
  - pwdlib με Argon2 (hashing κωδικών)
- **Βάση:** PostgreSQL 16 σε Docker, με driver `psycopg` 3
- **Frontend:** React 19, Vite, React Router 7
- **Έλεγχος κώδικα:** oxlint

## Προϋποθέσεις

- Python 3.14 (η έκδοση με την οποία αναπτύχθηκε και επαληθεύτηκε το project)
- Node.js 20.19+ ή 22.12+ (απαίτηση του Vite)
- Docker Desktop

### Θύρες

| Θύρα | Υπηρεσία | Αλλάζει από |
|---|---|---|
| `5432` | PostgreSQL | `POSTGRES_PORT` στο `.env` |
| `8000` | Backend (uvicorn) | παράμετρος `--port` στο uvicorn |
| `5173` | Frontend (Vite) | `frontend/vite.config.js` |

Η θύρα 5173 είναι δηλωμένη ως `strictPort`, δηλαδή αν είναι πιασμένη το Vite
σταματάει αντί να διαλέξει άλλη.

Οι εντολές που ακολουθούν είναι για Windows με PowerShell.

## Ρυθμίσεις

Κατέβασε τον κώδικα:

```
git clone <URL του repository>
```

Μπες στον φάκελο που δημιουργήθηκε από το clone.

Αντίγραψε το `.env.example` σε `.env` στη ρίζα του project:

```
Copy-Item .env.example .env
```

Άνοιξε το `.env` και αντικατάστησε τις ενδεικτικές τιμές με δικές σου. Τα
`POSTGRES_USER`, `POSTGRES_PASSWORD` και `POSTGRES_DB` πρέπει να συμφωνούν με τα
αντίστοιχα στοιχεία στο `DATABASE_URL`. Άλλαξε επίσης το `SECRET_KEY` σε ένα
δικό σου τυχαίο κλειδί.

Το `.env` δεν ανεβαίνει στο git.

### Μεταβλητές περιβάλλοντος

| Μεταβλητή | Περιγραφή | Προεπιλογή / απαίτηση |
|---|---|---|
| `POSTGRES_USER` | Χρήστης της βάσης | — (υποχρεωτικό) |
| `POSTGRES_PASSWORD` | Κωδικός της βάσης | — (υποχρεωτικό) |
| `POSTGRES_DB` | Όνομα της βάσης | — (υποχρεωτικό, στο `.env.example`: `library_db`) |
| `POSTGRES_PORT` | Θύρα στην οποία εκτίθεται η βάση | `5432` |
| `DATABASE_URL` | Connection string για το backend | — (υποχρεωτικό) |
| `SECRET_KEY` | Κλειδί υπογραφής των JWT | — (υποχρεωτικό) |

Οι τέσσερις πρώτες χρησιμοποιούνται από το Docker Compose, ενώ οι δύο
τελευταίες διαβάζονται από το backend μέσω του `backend/app/config.py`.

Το `DATABASE_URL` πρέπει να συμφωνεί με τα ίδια στοιχεία σύνδεσης: τον ίδιο
χρήστη, τον ίδιο κωδικό, την ίδια βάση και την ίδια θύρα. Αν δεν ταιριάζουν, το
backend δεν θα συνδεθεί. Η μορφή του είναι:

```
postgresql+psycopg://ΧΡΗΣΤΗΣ:ΚΩΔΙΚΟΣ@localhost:5432/library_db
```

## Εγκατάσταση και εκτέλεση

Το backend και το frontend τρέχουν ταυτόχρονα σε δύο ξεχωριστά terminals. Και οι
δύο εντολές εκκίνησης μένουν ενεργές μέχρι να τις σταματήσεις με `Ctrl+C`.

### 1. Βάση δεδομένων

Από τη ρίζα του project:

```
docker compose up -d
```

Έλεγχος ότι ξεκίνησε:

```
docker compose ps
```

### 2. Backend

Από τον φάκελο `backend`:

```
python -m venv .venv
```

```
.venv\Scripts\activate
```

```
pip install -r requirements.txt
```

Δημιουργία των πινάκων και των αρχικών δεδομένων:

```
python create_tables.py
```

```
python seed.py
```

Και τα δύο μπορούν να ξανατρέξουν χωρίς πρόβλημα. Το `create_tables.py` δεν
πειράζει πίνακες που υπάρχουν ήδη και το `seed.py` σταματάει αν βρει ήδη τα
αρχικά δεδομένα στη βάση. Οι πίνακες παράγονται από τα SQLAlchemy models, δεν
υπάρχει χειρόγραφο SQL.

Εκκίνηση του API:

```
uvicorn app.main:app --reload
```

### 3. Frontend

Από τον φάκελο `frontend`, σε νέο terminal:

```
npm install
```

```
npm run dev
```

Άνοιξε το `http://localhost:5173`.

> Κατά την ανάπτυξη το frontend πρέπει να ανοίγει ως `localhost` και όχι ως
> `127.0.0.1`, γιατί το CORS του backend επιτρέπει μόνο το
> `http://localhost:5173`.

## Διευθύνσεις και τεκμηρίωση του API

| Τι | Διεύθυνση |
|---|---|
| Εφαρμογή | `http://localhost:5173` |
| API | `http://127.0.0.1:8000` |
| Swagger UI | `http://127.0.0.1:8000/docs` |
| ReDoc | `http://127.0.0.1:8000/redoc` |
| OpenAPI schema | `http://127.0.0.1:8000/openapi.json` |
| Health check | `http://127.0.0.1:8000/health` |

Τα endpoints είναι χωρισμένα σε έξι ομάδες: `auth`, `catalog`, `loans`,
`members`, `requests` και `users`. Η πλήρης τεκμηρίωση είναι διαθέσιμη σε
Swagger UI και ReDoc.

Για τα προστατευμένα endpoints, πάτησε «Authorize» στο Swagger UI και
χρησιμοποίησε τα στοιχεία ενός από τους δοκιμαστικούς λογαριασμούς. Το Swagger
χρησιμοποιεί το `/api/auth/login` για την έκδοση του token.

## Build και deploy

### Build

Το backend δεν έχει βήμα build. Τρέχει απευθείας με uvicorn από τον πηγαίο
κώδικα, αφού εγκατασταθούν τα πακέτα του `requirements.txt`.

Το frontend χτίζεται από τον φάκελο `frontend`:

```
npm run build
```

Το αποτέλεσμα παράγεται στο `frontend/dist` και είναι στατικά αρχεία: ένα
`index.html` και ο φάκελος `assets` με το JavaScript και το CSS.

Τοπική δοκιμή του build:

```
npm run preview
```

### Deploy

Για να τρέξει το project σε άλλο μηχάνημα χρειάζονται τέσσερα πράγματα:

1. **PostgreSQL.** Είτε με το `docker compose up -d` του project, είτε με μια
   υπάρχουσα βάση PostgreSQL 16.
2. **Μεταβλητές περιβάλλοντος.** Ένα `.env` όπως περιγράφεται παραπάνω, με το
   `DATABASE_URL` να δείχνει στη βάση και ένα δικό του `SECRET_KEY`.
3. **Backend.** Εγκατάσταση των πακέτων, `python create_tables.py`, και μετά
   `uvicorn app.main:app` — χωρίς το `--reload`, που είναι μόνο για ανάπτυξη.
4. **Frontend.** `npm run build` και σερβίρισμα του περιεχομένου του
   `frontend/dist` από οποιονδήποτε στατικό server.

Τα αρχεία του `dist` είναι στατικά και δεν χρειάζονται Node για να σερβιριστούν.
Επειδή το frontend χρησιμοποιεί `BrowserRouter`, ο static server πρέπει να
επιστρέφει το `index.html` και για τα frontend routes. Σε παραγωγή συνήθως
μπαίνει ένας reverse proxy μπροστά από τα δύο, που σερβίρει το `dist` και
προωθεί το `/api` στο uvicorn.

Δύο διευθύνσεις είναι γραμμένες μέσα στον κώδικα και πρέπει να αλλάξουν αν το
project τρέξει σε άλλες διευθύνσεις από τις τοπικές:

- `BASE_URL` στο `frontend/src/api.js` — πού βρίσκεται το API.
- `allow_origins` στο `backend/app/main.py` — ποια origins δέχεται το CORS.

## Ρόλοι και δικαιώματα

Η εφαρμογή έχει τρεις ρόλους.

| Ρόλος | Τι μπορεί να κάνει |
|---|---|
| **MEMBER** | Βλέπει τον κατάλογο, υποβάλλει αιτήματα δανεισμού και παρακολουθεί τα δικά του αιτήματα και δανεισμούς |
| **LIBRARIAN** | Διαχειρίζεται βιβλία, αντίτυπα, αιτήματα και δανεισμούς |
| **ADMIN** | Ό,τι και ο LIBRARIAN, και επιπλέον διαχειρίζεται τους χρήστες |

Ο κατάλογος και οι σελίδες των βιβλίων είναι ορατά και χωρίς σύνδεση.

Η σύνδεση γίνεται με JWT. Ο κωδικός αποθηκεύεται ως hash με Argon2 και
δεν επιστρέφεται ποτέ από το API. Το token ισχύει για 60 λεπτά.

Τα δικαιώματα ελέγχονται και στα δύο άκρα: στο backend με dependencies
(`require_member`, `require_staff`, `require_admin`) πάνω στα endpoints, και στο
frontend με τα εξής: οι προστατευμένες σελίδες ελέγχονται με το
`ProtectedRoute`, ενώ οι σύνδεσμοι πλοήγησης εμφανίζονται ανάλογα με τον ρόλο
του χρήστη.

## Λειτουργίες

**Χωρίς σύνδεση**

- Κατάλογος βιβλίων με διαθεσιμότητα αντιτύπων
- Αναζήτηση με τίτλο και φίλτρο ανά κατηγορία
- Σελίδα βιβλίου με στοιχεία έκδοσης
- Εγγραφή νέου μέλους

**Μέλος**

- Αίτημα δανεισμού για ένα βιβλίο, με έλεγχο ότι δεν υπάρχει ήδη ενεργό αίτημα
  για το ίδιο βιβλίο
- Λίστα με τα αιτήματά του και την κατάστασή τους
- Λίστα με τους δανεισμούς του, τις ημερομηνίες επιστροφής και τα πρόστιμα

**Προσωπικό**

- Δημιουργία, επεξεργασία και διαγραφή βιβλίων. Βιβλίο με ιστορικό δανεισμών ή
  αιτημάτων δεν διαγράφεται
- Δημιουργία συγγραφέων και κατηγοριών μέσα από τη φόρμα του βιβλίου
- Προσθήκη αντιτύπων και σήμανσή τους ως χαμένων ή επαναφορά τους σε διαθέσιμα
- Έγκριση, απόρριψη, παραλαβή και ακύρωση αιτημάτων. Η παραλαβή δεσμεύει ένα
  διαθέσιμο αντίτυπο και δημιουργεί τον δανεισμό
- Λίστα όλων των δανεισμών με ένδειξη καθυστέρησης, και καταγραφή επιστροφής

**Διαχειριστής**

- Λίστα χρηστών, δημιουργία λογαριασμών προσωπικού, αλλαγή ρόλου και
  ενεργοποίηση ή απενεργοποίηση λογαριασμών

Η περίοδος δανεισμού είναι 14 ημέρες και το πρόστιμο 0,50 € για κάθε ημέρα
καθυστέρησης, υπολογισμένο κατά την επιστροφή.

## Αρχιτεκτονική και δομή

Το backend είναι χωρισμένο σε στρώματα:

```
router  ->  service  ->  repository  ->  model
```

- Οι **routers** χειρίζονται μόνο το HTTP κομμάτι: παραλαβή του αιτήματος,
  έλεγχο δικαιωμάτων και μετατροπή των σφαλμάτων του service σε κωδικούς HTTP.
- Τα **services** έχουν τους κανόνες του domain και δεν γνωρίζουν HTTP.
- Στην κανονική ροή της εφαρμογής, τα **repositories** συγκεντρώνουν την
  πρόσβαση στη βάση και δεν κάνουν commit· το commit γίνεται στο service.

```
backend/
  app/
    models/         οι οντότητες και οι σχέσεις τους
    repositories/   πρόσβαση στη βάση
    services/       κανόνες του domain
    routers/        τα endpoints
    schemas/        Pydantic schemas για είσοδο και έξοδο
    config.py       ρυθμίσεις από το .env
    database.py     session και base των models
    dependencies.py get_db και οι έλεγχοι ρόλων
    security.py     hashing κωδικών και JWT
    main.py         η εφαρμογή FastAPI και το CORS
  create_tables.py
  seed.py
  requirements.txt
frontend/
  src/
    pages/          μία ανά οθόνη
    components/     Layout, ProtectedRoute, BookCopies
    AuthContext.jsx κατάσταση σύνδεσης
    api.js          κλήσεις προς το API
    index.css
docker-compose.yml
.env.example
```

Οι οντότητες του domain είναι: `User`, `Member`, `Book`, `BookCopy`, `Author`,
`Category`, `Loan` και `LoanRequest`.

## Επίλυση προβλημάτων

**Το `docker compose up -d` αποτυγχάνει.** Βεβαιώσου ότι το Docker Desktop είναι
ανοιχτό και σε λειτουργία.

**Το `.venv\Scripts\activate` δεν εκτελείται.** Σε PowerShell με περιοριστική
πολιτική εμφανίζεται «running scripts is disabled on this system». Τρέξε
`Set-ExecutionPolicy -Scope Process RemoteSigned` στο ίδιο παράθυρο και δοκίμασε
ξανά.

**Το backend δεν συνδέεται στη βάση.** Έλεγξε ότι το `DATABASE_URL` έχει τον
ίδιο χρήστη, κωδικό, όνομα βάσης και θύρα με τα `POSTGRES_*`. Είναι το πιο
συχνό λάθος στο `.env`.

**Η θύρα 5432 είναι πιασμένη.** Αν τρέχει ήδη PostgreSQL στον υπολογιστή,
άλλαξε το `POSTGRES_PORT` στο `.env` σε κάτι άλλο, π.χ. `5433`, και ενημέρωσε
αντίστοιχα και τη θύρα μέσα στο `DATABASE_URL`.

**Το frontend δεν φτάνει στο API.** Άνοιξε το `http://localhost:5173` και όχι
το `http://127.0.0.1:5173`. Το CORS του backend επιτρέπει μόνο το πρώτο.

**Το Vite σταματάει με μήνυμα για τη θύρα.** Η 5173 είναι δηλωμένη ως
`strictPort`. Κλείσε ό,τι άλλο την κρατάει ή άλλαξέ την στο
`frontend/vite.config.js`.

**Το `seed.py` δεν βάζει δεδομένα.** Σταματάει επίτηδες αν βρει ήδη τα αρχικά
δεδομένα στη βάση, ώστε να μην τα διπλασιάσει.
